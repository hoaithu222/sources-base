# Hướng dẫn đa ngôn ngữ — thêm chuỗi, namespace, ngôn ngữ

> Đọc xong là tự làm được: thêm một chuỗi, thêm một file thông điệp, thêm một ngôn ngữ, đổi ngôn ngữ giao diện, dịch ở Server vs Client Component, viết test.
> File này là HƯỚNG DẪN, không đặt luật: luật nằm ở [`rules/i18n/i18n.md`](../rules/i18n/i18n.md); lý do thiết kế: [`architecture.md`](../architecture.md) §5.
> Mọi tên file / hàm dưới đây là code THẬT (ngôn ngữ `ja` và namespace `invoice` là ví dụ minh hoạ — chép rồi đổi tên); thấy lệch thì code là nguồn thật, sửa file này trong cùng PR.

## 2. Thêm một chuỗi

**Ví dụ:** nút "Xuất báo cáo" ở màn Cài đặt (namespace `account`).

1. Chọn namespace + vị trí: chữ của màn nào nằm trong file của feature đó, nhóm con theo màn / component (`account.settings.*`). Dùng lại được thì tìm ở `ui.common` / `common` trước (`rules/i18n/i18n.md` §4).
2. Thêm khoá vào **CẢ HAI** file, cùng cấu trúc:

```jsonc
// src/messages/vi/account.json  → trong "settings": { … }
"exportReport": "Xuất báo cáo",
// src/messages/en/account.json  → cùng vị trí
"exportReport": "Export report",
```

3. Dùng trong component:

```tsx
'use client';                                      // account nằm trong CLIENT_NAMESPACES nên dùng được ở client
import { useTranslations } from 'next-intl';

const t = useTranslations('account.settings');     // viết literal để check:i18n nhận ra namespace
<Button>{t('exportReport')}</Button>
```

4. Chữ có biến / số nhiều (`rules/i18n/i18n.md` §5):

```jsonc
// vi: tiếng Việt không chia số ít / nhiều — chỉ chèn biến
"selectedCount": "{count} dòng đã chọn",
// en: ICU plural
"selectedCount": "{count, plural, one {# row selected} other {# rows selected}}",
```
```tsx
t('selectedCount', { count: rows.length })
```

5. Chạy `npm run typecheck && npm run check:i18n`. Thiếu khoá ở `en` → `tsc` đỏ (`satisfies Messages`); khác tên biến giữa hai ngôn ngữ → `check:i18n` đỏ.

Chữ của `<title>` / description một trang: KHÔNG thêm ở đây mà ở `metadata.<key>` — `guides/seo.md` §1.

## 3. Thêm một namespace (file JSON mới)

**Khi nào:** một feature / vùng mới có nhiều chữ (`invoice`), hoặc một nhóm mới của UI kit (`ui.<nhóm>`). Chữ lẻ của màn có sẵn thì thêm vào namespace hiện có, đừng tạo file.

1. Tạo `invoice.json` trong CẢ `src/messages/vi/` và `src/messages/en/` (cùng cấu trúc khoá; JSON hợp lệ — không dấu phẩy thừa).
2. Gắn vào **CẢ HAI** `index.ts` — import + thêm vào object `messages` (giữ thứ tự chữ cái):

```ts
// src/messages/vi/index.ts  (và y hệt ở src/messages/en/index.ts)
import invoice from './invoice.json';
…
const messages = { about, account, auth, common, errors, invoice, landing, metadata, shell, site, ui, validation };
```

   Nhóm UI kit: file `ui.<nhóm>.json` → import `uiXxx` + thêm vào object `ui` (`ui = { common: uiCommon, …, xxx: uiXxx }`) ở cả hai `index.ts`.
3. **Client Component có dùng namespace này không?**
   - Có → thêm `'invoice'` vào `CLIENT_NAMESPACES` (`src/core/i18n/messages.ts`). Chấp nhận: namespace đi xuống trình duyệt ở MỌI trang — giữ nhỏ.
   - Chỉ Server Component (trang công khai, SEO, nội dung tĩnh) → KHÔNG thêm; dịch ở server, truyền chuỗi xuống bằng props.
4. `npm run typecheck` — `Messages` tự có khoá mới; `useTranslations('invoice')` có gợi ý.
5. `npm run check:i18n` — khoá phải có ở mọi ngôn ngữ, không mồ côi.

> Quên thêm vào `index.ts` của `vi` → `Messages` thiếu namespace, `t()` đỏ. Quên ở `en` → `satisfies Messages` đỏ. Quên `CLIENT_NAMESPACES` → KHÔNG đỏ ở build, lỗi "MISSING_MESSAGE" lúc chạy ở trình duyệt (§9).

## 4. Thêm một ngôn ngữ

**Ví dụ:** tiếng Nhật `ja`. Mục đích của TypeScript ở đây: `Record<Locale, …>` ở mọi chỗ theo ngôn ngữ báo đỏ cho tới khi đủ — làm lần lượt, chạy `npm run typecheck` sau mỗi bước.

| # | Việc | File |
|---|---|---|
| 1 | Thêm mã vào `LOCALES` và khai `LOCALE_META.ja` (`label` viết bằng CHÍNH ngôn ngữ đó, `shortLabel`, `htmlLang`, `hrefLang`, `ogLocale` dạng `ja_JP`) | `src/core/i18n/locales.ts` |
| 2 | Tạo thư mục thông điệp: chép thư mục `en` thành `ja` (cùng cha `src/messages/`), dịch từng file; `ja/index.ts` khai `satisfies Messages` | `src/messages/<mã>/` |
| 3 | Đăng ký bộ nạp | `LOADERS` ở `src/core/i18n/messages.ts`: `ja: () => import('@/messages/<mã>')` |
| 4 | Locale của Zod (câu lỗi mặc định) | `ZOD_LOCALES` ở `src/core/config/configure-zod-locale.ts`: `ja: () => z.locales.ja()` |
| 5 | Định dạng số / ngày / tiền / "vừa xong" | `INTL_LOCALE` · `DATE_FORMAT` · `JUST_NOW` ở `src/shared/utils/format/format.utils.ts`; `MONEY_UNITS` ở `src/shared/utils/format/money.utils.ts` |
| 6 | Màn lỗi toàn cục (không có provider) | `SCREENS` ở `src/app/global-error.tsx` (import `errors.json` của ngôn ngữ mới); `src/app/global-not-found.tsx` đang hiện vi + en — thêm dòng nếu muốn |
| 7 | Font ảnh Open Graph nếu chữ không nằm trong Noto Sans `latin` / `vietnamese` (Hán, Thái, Ả Rập…) | thêm file `.woff` ở `src/assets/fonts/og/` + mảng `fonts` ở `src/app/[locale]/opengraph-image.tsx` |
| 8 | Test dùng thông điệp thật | `MESSAGES` ở `tests/helpers/render.tsx` |

```ts
// 1) src/core/i18n/locales.ts
export const LOCALES = ['vi', 'en', 'ja'] as const;
export const LOCALE_META: Record<Locale, LocaleMeta> = {
  vi: { … },
  en: { … },
  ja: { label: '日本語', shortLabel: 'JA', htmlLang: 'ja', hrefLang: 'ja', ogLocale: 'ja_JP' },
};
// 4) mã locale của Zod đôi khi khác (ptBR, frCA…): xem Object.keys(z.locales); chưa có thì rơi về z.locales.en()
```

**Những thứ TỰ CÓ, không phải sửa:** URL `/ja/…` (`routing` đọc `LOCALES`), `generateStaticParams` (SSG sinh thêm `/ja/*`), `proxy.ts`, `<html lang>`, hreflang + `x-default` trong metadata, `sitemap.xml`
(mỗi route một mục cho `ja`, kèm `alternates`), `robots.txt` (`Disallow` bản `/ja/…` của đường riêng tư), `LocaleSwitcher` và `LanguageGroup` (liệt kê `LOCALES`), `og:locale:alternate`.

**Kiểm sau khi thêm:**

1. `npm run typecheck && npm run check:i18n` xanh (không còn khoá thiếu / biến lệch).
2. `npm run build` — bảng `Route (app)` có thêm `/ja/…` đều `●` / `○` (tĩnh), không `ƒ`.
3. `npm start` rồi: `curl -s http://localhost:3000/ja/about | grep -oE '<html[^>]*lang="[a-z-]+"|link rel="alternate"[^>]*>'` — `lang="ja"` + đủ hreflang `vi · en · ja · x-default`;
   `curl -s http://localhost:3000/sitemap.xml` có mục `/ja/about`; `curl -sI http://localhost:3000/ja/opengraph-image` trả `image/png`.
4. Mở `/ja` và `/ja/settings` (đổi ngôn ngữ bằng Cài đặt) — không còn chữ tiếng Việt / Anh lọt vào; chữ dài không làm vỡ bố cục.

**Còn cố định tiếng Việt (biết trước):** `stripDiacritics` / `normalizeSearch` (bỏ dấu tiếng Việt — vô hại với ngôn ngữ khác) và `localeCompare(…, 'vi')` ở `table-sort.utils.ts` (so sánh chuỗi
khi sắp xếp bảng). Ngôn ngữ cần thứ tự sắp xếp riêng thì đưa `locale` vào đó, đừng rẽ nhánh ở chỗ gọi.

> Bỏ một ngôn ngữ: làm ngược lại, và nhớ giữ chuyển hướng cho URL cũ (`/ja/…`) nếu đã từng được lập chỉ mục.

## 5. Đổi ngôn ngữ trên giao diện

| Nơi | Component | Cách hoạt động |
|---|---|---|
| Header trang công khai | `LocaleSwitcher` (`src/app/_components/LocaleSwitcher.tsx`) | Mỗi ngôn ngữ là `<Link locale href={pathname}>` THẬT → `<a hreflang href="/en/about">`: bot lần theo được bản dịch, chuột phải mở tab mới được, không cần JS |
| Cài đặt (vùng làm việc) | `LanguageGroup` (`src/app/_views/settings/LanguageGroup.tsx`) | `router.replace(pathname + search, { locale })` — giữ query string; next-intl ghi cookie `NEXT_LOCALE` |

- Đổi ngôn ngữ = chuyển sang URL tương ứng (`/settings` ⇄ `/en/settings`) — KHÔNG state ngôn ngữ trong store. `LocaleSync` nạp lại câu lỗi HTTP + locale Zod khi `useLocale()` đổi.
- Muốn thêm nút đổi ngôn ngữ ở nơi khác: dùng `LocaleSwitcher` (liên kết) cho trang công khai; trong vùng làm việc dùng mẫu `router.replace(…, { locale })`. KHÔNG tự sửa chuỗi URL.
- Cookie `NEXT_LOCALE` ghi nhớ lựa chọn; người vào `/` với cookie / `Accept-Language: en` có thể được chuyển sang `/en` (next-intl `localeDetection`).

## 6. Server Component vs Client Component

```tsx
// ── Server Component, ĐỒNG BỘ (layout, view tĩnh) — cùng hook như client
import { useTranslations } from 'next-intl';
export default function PublicFooter() {
  const t = useTranslations('site.footer');          // namespace `site` chỉ ở server — đúng chỗ
  return <footer>{t('tagline')}</footer>;
}

// ── Server Component ASYNC / generateMetadata — hook không dùng được sau await
import { getTranslations, requireLocale } from '@/core/i18n/server';
export async function generateMetadata({ params }: PageProps<'/[locale]/about'>) {
  const locale = requireLocale((await params).locale);                       // ngôn ngữ lạ → 404
  const t = await getTranslations({ locale, namespace: 'metadata.about' });  // PHẢI truyền locale
  …
}

// ── Client Component — chỉ namespace trong CLIENT_NAMESPACES
'use client';
import { useLocale, useTranslations } from 'next-intl';
const t = useTranslations('auth.login');
const locale = useLocale();                          // 'vi' | 'en' — truyền cho formatNumber / formatDate
```

| Tình huống | Làm |
|---|---|
| Client Component cần chữ của namespace server-only (`landing`, `about`, `site`, `metadata`) | Dịch ở Server Component cha, truyền xuống bằng props — hoặc thêm namespace vào `CLIENT_NAMESPACES` (đắt) |
| Cần cả `t` lẫn `locale` ở server async | `const locale = requireLocale((await params).locale)` rồi `getTranslations({ locale, namespace })` |
| Cần đọc mảng / object thô (vd `keywords`) | `t.raw('keywords')` ở server |
| Có thẻ trong câu (in đậm, liên kết) | `t.rich('key', { b: (chunks) => <strong>{chunks}</strong> })` |
| Cần `Link` / chuyển trang | `@/core/i18n` (Server Component dùng `Link` được; hook `useRouter` / `usePathname` là client) |

- ⛔ Client Component KHÔNG import `@/core/i18n/server`. Server file import `@/core/i18n` (không `/server`) vẫn được cho `Link` / `LOCALES` / `LOCALE_META` / `isLocale`.
- Không cần `setRequestLocale` — ngôn ngữ đến từ tham số route (`core/i18n/request.ts`), trang vẫn SSG.

## 7. Hàm thuần, Zod, lỗi HTTP, định dạng

| Việc | Cách | Chi tiết |
|---|---|---|
| Hiển thị số / tiền / ngày | `formatNumber(value, decimals, minDecimals, locale)` · `formatCurrency(value, currency, locale)` · `formatDate(date, format, locale)` — component truyền `useLocale()` | `rules/i18n/i18n.md` §7 |
| Câu lỗi Zod chung | `emailField()` · `requiredText()`… không truyền `msg` → tự theo ngôn ngữ; câu mới thêm vào `validation.json` MỌI ngôn ngữ | `rules/data/form-validation.md` §6 |
| Câu lỗi Zod riêng của feature | `createXxxSchemas(messages)` + `useXxxSchemas()` (mẫu `src/features/auth/schemas`) | như trên |
| Câu lỗi HTTP / mã lỗi BE mới | thêm khoá vào `errors.json` → `http.codes` MỌI ngôn ngữ; đọc qua `errorMessages()` | `rules/data/api-patterns.md` §3 |
| Hằng chứa chữ (menu, bảng cột, options) | giữ `id` / khoá ở hằng, `t()` lúc render (mẫu `FEATURES` ở `LandingView`) | `rules/i18n/i18n.md` §1 |

- Menu / điều hướng: id là khoá ở `shell.json` → `nav.<id>.{title,subtitle,description}` (`src/app/_navigation`); thêm phân hệ là thêm khoá ở CẢ hai ngôn ngữ (TypeScript đỏ nếu thiếu — `NavId` suy từ `Messages`).
- ⛔ `configureZodLocale` chỉ ở trình duyệt (`LocaleSync` đã gọi). Đừng gọi trong Server Component.

## 8. Kiểm thử

Component có `useTranslations` / `Link` / `useRouter` của `@/core/i18n` PHẢI dựng trong provider next-intl — `render` trần của Testing Library ném "No intl context found". Dùng helper ở `tests/helpers/render.tsx`:

```tsx
import { renderInRouter, renderWithIntl } from '@tests/helpers/render';

renderWithIntl(<ConfirmDialog open … />);                          // thông điệp THẬT, mặc định tiếng Việt
renderWithIntl(<LocaleSwitcher />, { locale: 'en' });              // kiểm bản tiếng Anh
const { router } = renderInRouter(<Header />, { pathname: '/en/about', locale: 'en' });
expect(router.push).toHaveBeenCalledWith('/dashboard');            // `navigation-mock`: next/navigation được mock ở tests/setup.ts
```

- Test dùng thông điệp thật → câu trong `getByText` là chữ tiếng Việt thật (đổi chữ thì sửa test). Chữ không quan trọng: truy vấn theo `role` + `name` hoặc theo khoá qua `useMessages`.
- Hàm thuần (`formatNumber`, validator, `buildAlternates`, `localizedPath`) test thẳng, không cần provider — truyền `locale` / bộ câu giả.
- Server Component bất đồng bộ không render được trong jsdom: test phần thuần (`build*` của `core/seo`, `generatePageMetadata` qua mock `getTranslations`) và kiểm trang bằng `npm run build` + `curl` (`guides/seo.md` §5).
- Cả hai ngôn ngữ: component có chữ ảnh hưởng bố cục (nút, chip, bảng) nên kiểm thêm `{ locale: 'en' }`.

## 9. Lỗi thường gặp

| Hiện tượng | Nguyên nhân | Sửa |
|---|---|---|
| Console / trang: `MISSING_MESSAGE: … (vi)` ở trình duyệt, build vẫn xanh | Client Component dùng namespace KHÔNG có trong `CLIENT_NAMESPACES` (`landing`, `metadata`, `site`, `about`) | Dịch ở server rồi truyền props, hoặc thêm vào `CLIENT_NAMESPACES` |
| `Property '…' does not exist` khi gõ `t('…')` | Khoá chưa có ở `vi` (nguồn), hoặc chưa import file JSON vào `vi/index.ts` | Thêm khoá / import; chạy lại `npm run typecheck` |
| `tsc` đỏ ở `en/index.ts` ("not assignable … satisfies Messages") | Thiếu / thừa khoá so với `vi` | Đồng bộ khoá (tìm bằng `npm run check:i18n`) |
| `check:i18n`: "biến ICU lệch" | `vi` `{count}` ↔ `en` `{n}`, hoặc quên biến | Dùng CÙNG tên biến ở mọi ngôn ngữ |
| "No intl context found" trong test | Dựng bằng `render` trần | `renderWithIntl` / `renderInRouter` (§8) |
| Hydration mismatch ở ngày / số | Định dạng theo múi giờ / locale khác nhau giữa server và client | Dùng `formatDate(…, locale)` với dữ liệu ổn định; thứ chỉ có ở client (giờ hiện tại) tính sau mount |
| Bấm liên kết đang ở `/en/…` lại về tiếng Việt | Dùng `next/link` / `useRouter` của `next/navigation` | `Link` / `useRouter` của `@/core/i18n` (ESLint chặn) |
| `/en/en/...` | Truyền `href` đã có `/en` cho `Link` / `router` của `@/core/i18n`; hoặc dùng `useRouter` của `@/core/i18n` với URL lấy từ `<a>` | `href` là path KHÔNG tiền tố (`PATHS.*`); URL đầy đủ thì dùng router của `next/navigation` (như `useDirtyGuard`) |
| Chuỗi có `'` hoặc `{` hiển thị sai | ICU coi `{…}` là biến, `'` là ký tự thoát | Bọc `'{'` cho dấu ngoặc nhọn thật; thử bằng cách mở trang |
| ``t(`a.${x}`)`` báo kiểu | `x` là `string`, không phải union literal | Thu hẹp `x` thành union (`as const`) hoặc `satisfies` bảng khoá |
| Chữ cứng không bị lint bắt | `guard/i18n-text` chỉ bắt chữ CÓ DẤU tiếng Việt | Review bắt chữ tiếng Anh cứng (`rules/i18n/i18n.md` §1) |
| Thêm ngôn ngữ nhưng `/ja/...` 404 | `LOCALES` có `ja` nhưng thiếu `LOADERS.ja` / thư mục thông điệp (hoặc chưa build lại) | Làm đủ §4; `npm run build` lại |
| Sau khi đổi ngôn ngữ, câu lỗi form vẫn ngôn ngữ cũ | Schema dựng ở module-level bằng chuỗi đã tra sẵn | Dùng helper đọc lười (`validationMessages()`) hoặc `useXxxSchemas()` (`form-validation.md` §6) |
