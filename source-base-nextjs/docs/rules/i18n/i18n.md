# Quy tắc đa ngôn ngữ (BẮT BUỘC)

> Áp dụng cho **mọi chữ người dùng nhìn thấy hoặc nghe thấy**: nhãn, placeholder, `aria-label`, `title`, toast, câu lỗi, trạng thái rỗng, `alt`,
> tiêu đề tab / mô tả SEO, ngày / số / tiền. Base chạy hai ngôn ngữ (`vi` mặc định · `en`) bằng **next-intl**; mỗi chữ cứng là một chỗ phải
> sửa lại khi thêm ngôn ngữ, và là một chỗ người dùng tiếng Anh thấy tiếng Việt.
> Vi phạm mục **⛔** → **block merge**. Hướng dẫn từng bước: `docs/guides/i18n.md` · kiến trúc: `architecture.md` §5.

| # | Luật | Máy giữ |

## 1. ⛔ Mọi chữ hiển thị đi qua next-intl

```tsx
// ❌ SAI — chữ cứng (cả tiếng Việt lẫn tiếng Anh)
<Button>Lưu thay đổi</Button>
<Input placeholder="Search…" aria-label="Tìm kiếm" />
showToast('success', 'Đã lưu');

// ✅ ĐÚNG — Client Component
'use client';
const t = useTranslations('ui');              // khoá thật: `ui.common.save`, `ui.common.search`
<Button>{t('common.save')}</Button>
<Input aria-label={t('common.search')} placeholder={t('common.search')} />
const tRegister = useTranslations('auth.register');
showToast('success', tRegister('success'));

// ✅ ĐÚNG — Server Component (đồng bộ): cùng API
const t = useTranslations('landing');
// ✅ ĐÚNG — Server Component async / generateMetadata: phải truyền locale
const t = await getTranslations({ locale, namespace: 'metadata.about' }); // `@/core/i18n/server`
```

- ⛔ **Không chữ mặc định trong component.** `cancelLabel = 'Huỷ'` hay `title ?? 'Thông báo'` là chữ cứng trá hình. Prop chữ để tuỳ chọn và rơi về khoá dịch:
  `{cancelLabel ?? t('common.cancel')}` (mẫu: `ConfirmDialog`, `useTranslations('ui')`).
- ⛔ **Không ghép câu bằng cách nối chuỗi** (`t('a') + ' ' + name`): trật tự từ khác nhau giữa các ngôn ngữ. Một câu = một khoá, phần động là biến ICU:
  `t('welcome', { name })` với `"welcome": "Chào {name}"` / `"Welcome, {name}"`.
- ⛔ **Không để chữ dịch ở hằng module-level** — lúc đó chưa có `t`. Giữ DỮ LIỆU (id, icon, khoá) và dịch lúc render:
  ``const FEATURES = [{ id: 'data', icon: 'folder' }, …] as const`` rồi ``t(`features.items.${id}.title`)`` (mẫu: `LandingView`, khoá `landing.features.items.<id>`).
- ⛔ **Văn bản dài / nội dung trang** (landing, giới thiệu, điều khoản) cũng là message, không phải JSX cứng — để bản dịch không đụng vào code.
- `aria-label`, `title`, `alt`, `placeholder`, nội dung toast, câu `EmptyState`, tiêu đề trang đều tính là chữ hiển thị. Ảnh trang trí: `alt=""` (không phải khoá).
- ⚠️ `guard/i18n-text` chỉ bắt chữ CÓ DẤU tiếng Việt (JSX text, giá trị prop, tham số toast). Chữ tiếng Anh cứng (`placeholder="Search…"`) và chuỗi dựng ở biến rồi mới đưa vào JSX
  lint KHÔNG thấy — review là lớp chặn còn lại, đừng coi "lint xanh" là "hết chữ cứng".
- Ngoại lệ có lý do thì `eslint-disable-next-line guard/i18n-text` kèm câu giải thích (vd. chữ mẫu trong trang trưng bày UI kit không đi vào sản phẩm) — không tắt cả file.

## 2. ⛔ Khoá có ở MỌI ngôn ngữ

`src/messages/vi/` là **NGUỒN**: kiểu `Messages` suy từ `vi/index.ts` (`core/i18n/messages.ts`). `en/index.ts` khai `satisfies Messages` nên thiếu / thừa khoá là `tsc` đỏ.

| Lệnh | Bắt gì |
|---|---|
| `npm run typecheck` | Khoá thiếu / thừa giữa các ngôn ngữ (kiểu); `t('khoá.sai')` |
| `npm run check:i18n` | ⛔ **khoá lệch** (thiếu / thừa ở ngôn ngữ ≠ `vi`) · ⛔ **biến lệch** (`{count}` có ở `vi` mà `en` đổi tên / quên) · ⛔ **thiếu khoá** (`t('…')` trỏ khoá không có — cả khoá dựng bằng chuỗi) · ⚠️ **mồ côi** (khoá không ai dùng; `--strict` biến thành lỗi) |

- Thêm khoá = thêm vào **tất cả** `messages/<locale>/<namespace>.json` CÙNG commit. Để `en` rỗng / chép tiếng Việt "tạm" là lỗi review — bản dịch tạm vẫn phải là tiếng Anh thật.
- Đổi ý nghĩa một câu → đổi ở mọi ngôn ngữ; đổi TÊN khoá → đổi ở mọi ngôn ngữ + mọi chỗ gọi (`tsc` chỉ ra).
- ⛔ Viết đúng dạng `const t = useTranslations('namespace')` (literal) để `check:i18n` nhận ra khoá thuộc namespace nào. Khoá dựng động (``t(`shortcuts.items.${id}`)``) được tính là dùng cả
  nhóm `shortcuts.items.*` — nhớ đủ MỌI giá trị `id` có khoá (để `id` là union literal thì `tsc` bắt thiếu).
- Khoá chạy qua `t.raw` / đọc nguyên khối (`metadata.*`, `validation.*`, `errors.http.*`, `ui.common.*`) được coi là luôn dùng — `check:i18n` không báo mồ côi cho chúng.

## 3. Namespace — file nào, ai được đọc

`src/messages/<locale>/<namespace>.json` → `useTranslations('<namespace>')`; file `ui.<nhóm>.json` gộp thành `ui.<nhóm>` (ghép ở `<locale>/index.ts`).

| Namespace | Nội dung | Client? |
|---|---|---|
| `common` | Chữ dùng khắp nơi (`sessionExpired`, `language.label`) | ✅ |
| `errors` | `http` (câu lỗi tầng HTTP — registry `errorMessages()`) + `screens` (màn lỗi / 404) | ✅ |
| `validation` | Câu lỗi Zod chung (registry `validationMessages()`) | ✅ |
| `ui` | UI kit: `ui.common` · `actions` · `dataDisplay` · `feedback` · `form` · `inputs` · `layout` · `media` · `navigation` · `overlays` · `pickers` · `primitives` · `selects` · `surfaces` · `utils` · `widgets` | ✅ |
| `auth` | Màn đăng nhập / đăng ký / quên mật khẩu (+ `auth.validation`) | ✅ |
| `shell` | Khung ứng dụng: menu (`nav.<id>`), header, bảng lệnh | ✅ |
| `account` | Hồ sơ, Cài đặt | ✅ |
| `metadata` | `<title>` / description từng trang, nền của root layout (`metadata.site`) | ❌ server |
| `landing` · `about` · `site` | Nội dung trang công khai, header / footer công khai | ❌ server |

**`CLIENT_NAMESPACES`** (`core/i18n/messages.ts`) là danh sách namespace gửi xuống trình duyệt qua `NextIntlClientProvider`; phần còn lại ở lại server để bundle nhỏ (nội dung SEO không tải
thêm byte JS nào).

- ⛔ **Client Component (`'use client'`) chỉ được `useTranslations` namespace trong `CLIENT_NAMESPACES`.** Dùng `landing` / `metadata` / `site` ở client → "MISSING_MESSAGE" lúc chạy (`tsc` không thấy).
  Cần chữ server-only ở client: (a) dịch ở Server Component rồi truyền xuống bằng props (ưu tiên), hoặc (b) thêm namespace vào `CLIENT_NAMESPACES` — chấp nhận bundle lớn hơn cho MỌI trang.
- Thêm namespace mới: JSON + gắn vào CẢ `vi/index.ts` lẫn `en/index.ts` + (nếu client dùng) `CLIENT_NAMESPACES`. Từng bước: `guides/i18n.md`.
- **Một feature = một namespace** cùng tên với feature (`auth`); chữ chỉ của một màn nằm trong nhóm con của nó (`account.settings.*`). Chữ dùng ≥ 2 feature → `common` / `ui.common`, không chép.
- Namespace client lớn dần là bundle trang đầu lớn dần: chữ của màn nặng mà chỉ một nhóm route dùng cân nhắc truyền qua props từ Server Component thay vì thêm vào `CLIENT_NAMESPACES`.

## 5. ICU — biến, số nhiều, lựa chọn

next-intl dùng ICU MessageFormat. Cả hai ngôn ngữ phải có **cùng tập biến** (`check:i18n` kiểm), dù cú pháp mỗi bên khác.

```jsonc
// en/shell.json — tiếng Anh có số ít / số nhiều
"screenCount": "{count, plural, one {# screen} other {# screens}}"
// vi/shell.json — tiếng Việt KHÔNG có số nhiều: chỉ cần chèn biến
"screenCount": "{count} màn hình"
```

- Tiếng Việt không chia số ít / nhiều → viết thẳng `{count} …`, KHÔNG dùng khối `plural` (vẫn phải có biến `count`). Ngôn ngữ thêm sau có nhiều dạng (Nga, Ả Rập) dùng `plural` đủ nhánh `one / few / many / other`.
- Chọn theo giá trị: `{month, select, 1 {January} 2 {February} … other {}}` (mẫu: `ui.pickers.monthLong`). Luôn có nhánh `other`.
- Số / ngày TRONG câu: để next-intl định dạng theo locale `{n, number}` · `{d, date, short}`, hoặc tính trước bằng `format.utils` rồi truyền chuỗi (§7). Không tự nối dấu `.` / `,`.
- Dấu ngoặc nhọn thật trong câu: bọc `'{'`. Dấu nháy đơn trong câu tiếng Anh ("don't") là ký tự thoát của ICU — thử trên trang trước khi commit.
- Đoạn có định dạng (in đậm, liên kết): `t.rich('key', { b: (chunks) => <strong>{chunks}</strong> })`; mảng / dữ liệu thô: `t.raw('keywords')` (chỉ ở server — nội dung `metadata`).

## 6. ⛔ Điều hướng, URL, `<html lang>`

**Chiến lược URL: `localePrefix: 'as-needed'`** (`core/i18n/routing.ts`) — ngôn ngữ mặc định `vi` KHÔNG tiền tố (`/login`), ngôn ngữ khác có (`/en/login`). Vì sao: URL tiếng Việt giữ nguyên (không mất xếp hạng cũ),
mỗi ngôn ngữ vẫn có địa chỉ riêng để công cụ tìm kiếm lập chỉ mục độc lập.

| Việc | Dùng | KHÔNG dùng |
|---|---|---|
| Liên kết nội bộ | `Link` từ `@/core/i18n` · `href` = path KHÔNG tiền tố (`PATHS.*`) | `next/link`, `<a href="/login">` |
| Điều hướng bằng code | `useRouter()` từ `@/core/i18n` (`push` · `replace`) | `useRouter` của `next/navigation` |
| Đường dẫn hiện tại | `usePathname()` từ `@/core/i18n` (đã bỏ tiền tố, so thẳng với `PATHS.*`) | `usePathname` của `next/navigation` |
| Redirect ở server | `redirect({ href, locale })` từ `@/core/i18n` | `redirect` của `next/navigation` |
| Đọc query / 404 | `useSearchParams` · `notFound` từ `next/navigation` (không phụ thuộc ngôn ngữ) | — |
| Đổi ngôn ngữ | `<Link locale="en" href={pathname}>` (`LocaleSwitcher`) · `router.replace(path, { locale })` (`LanguageGroup`) | Tự sửa chuỗi URL |

- ⛔ `next/link` và router của `next/navigation` bỏ mất ngôn ngữ đang chọn (đang ở `/en/about` bấm vào `/login` là về tiếng Việt). ESLint chặn; ngoại lệ phải có `eslint-disable-next-line` + lý do
  (`useDirtyGuard` giữ URL ĐÃ có tiền tố; `global-error.tsx` nằm ngoài provider).
- **`<html lang>`** = `LOCALE_META[locale].htmlLang` ở root layout — đúng ngôn ngữ cho SEO + trình đọc màn hình. Đoạn chữ ngôn ngữ khác trong trang thêm `lang` riêng (`LocaleSwitcher` đặt `lang={meta.htmlLang}` trên từng liên kết).
- **hreflang**: MỘT nguồn — Metadata API qua `buildPageMetadata` (`alternates.languages`, kèm `x-default` = `vi`) và `sitemap.xml`. `routing.alternateLinks: false` để next-intl không thêm header `Link` trùng lặp. Mỗi trang công khai PHẢI có hreflang đủ mọi ngôn ngữ — `rules/seo/seo.md`.
- **Ngôn ngữ đến từ tham số route** (`next/root-params`, `core/i18n/request.ts`), không từ header → mọi route `[locale]/…` vẫn **SSG**. KHÔNG gọi `setRequestLocale` (deprecated); KHÔNG đọc `cookies()` / `headers()` trong layout để biết ngôn ngữ.
- Mỗi entry server (`layout.tsx`, `page.tsx`, `generateMetadata`, `opengraph-image.tsx`) thu hẹp `params.locale` bằng `requireLocale(…)` (`@/core/i18n/server`): ngôn ngữ lạ → `notFound()` (404 đúng chuẩn).
- Cookie `NEXT_LOCALE` ghi nhớ lựa chọn (1 năm, `SameSite=Lax`). `proxy.ts` chạy middleware của next-intl nên người có cookie / `Accept-Language: en` vào `/` có thể được chuyển sang `/en` (`localeDetection` mặc định bật); bot không gửi các tín hiệu này nên luôn thấy bản `vi` ở `/`.
- Server Component dùng `Link` của `@/core/i18n` bình thường (không cần `'use client'`).

## 7. ⛔ Hàm thuần, registry lười — chữ ngoài React

`useTranslations` là hook: chỉ gọi trong component. Code ngoài React (hàm định dạng, validator Zod, tầng HTTP) nhận chữ theo MỘT trong ba cách:

| Loại | Cách | Nơi |
|---|---|---|
| Định dạng số / tiền / ngày / tương đối | Tham số cuối `locale: Locale` (mặc định `vi`) — component truyền `useLocale()` | `formatNumber` · `formatCurrency` · `formatPercent` · `formatDate` · `formatNow` · `formatRelativeTime` (`shared/utils/format/format.utils.ts`) · `formatMoneyCompact`… (`money.utils.ts`) |
| Câu lỗi Zod | Registry lười `validationMessages()` — đọc LÚC PARSE; helper `requiredText()` · `emailField()`… không truyền `msg` thì tự theo ngôn ngữ | `core/config/configure-zod-locale.ts` ← `messages/<locale>/validation.json` |
| Câu lỗi HTTP | Registry `errorMessages()` / `messageOfCode()` / `messageOfStatus()` | `core/http/errors/error-messages.ts` ← `messages/<locale>/errors.json` (`http`) |
| Schema riêng của feature | Factory thuần `createXxxSchemas(messages)` + hook `useXxxSchemas()` (`useTranslations` + `useMemo`) | mẫu `features/auth/schemas` |

- `LocaleSync` (`app/_providers`, trình duyệt) nạp hai registry mỗi khi ngôn ngữ đổi: `configureErrorMessages(messages.errors.http)` + `configureZodLocale(locale, messages.validation)`. Mặc định (chưa gọi — test, code chạy sớm) là tiếng Việt.
- ⛔ **`configureZodLocale` CHỈ ở trình duyệt.** Zod giữ cấu hình ở biến toàn cục: gọi trong Server Component thì ngôn ngữ của request này rò sang request khác.
- ⛔ **KHÔNG `toLocaleString` / `toLocaleDateString`** (`guard/number-format`) — dễ trộn `en-US` với `vi-VN` trong cùng màn. Dùng `format.utils`; cần `Intl` mới thì thêm vào đó, không rải ở chỗ gọi.
- ⛔ **KHÔNG `new AppError(kind, 'câu cứng')`** ở `core` (`guard/error-messages`): `new AppError(kind, errorMessages().timeout)`. Mã lỗi BE mới → khoá ở `errors.http.codes` MỌI ngôn ngữ.
- Hàm thuần mới cần chữ / định dạng theo ngôn ngữ: nhận `locale` (hoặc bộ câu đã dịch) qua tham số, không import `next-intl`. Nhờ vậy test được không cần provider.
  Kiểu / hằng thuần lấy từ `@/core/i18n/locales` (`Locale`, `DEFAULT_LOCALE`) — đường sâu này được phép riêng vì không kéo `next-intl/navigation` vào đồ thị (cùng `i18n/{server,routing,messages}`); còn lại import qua `@/core/i18n`.
- Hằng khai báo theo ngôn ngữ dùng `Record<Locale, …>` — thêm ngôn ngữ thì `tsc` báo đỏ mọi chỗ còn thiếu (`INTL_LOCALE`, `DATE_FORMAT`, `MONEY_UNITS`, `LOCALE_META`…).
- Số liệu: `tabular-nums` + `formatNumber(…, locale)`; KHÔNG hardcode `'.'` làm dấu nghìn.
- Chuỗi so sánh / tìm kiếm không theo `locale` (`normalizeSearch`, `matchesSearch` — `search-matching.md`).

## 8. Cái KHÔNG dịch

| Không dịch | Vì sao / làm gì |
|---|---|
| Log, `console.*`, cảnh báo dev (`warnUnpinnedFrozenColumns`…) | Dành cho lập trình viên; để tiếng Việt / Anh cố định |
| `EnvValidationError`, thông báo build / script | Dev-facing, chạy ngoài React |
| Tên thương hiệu, tên sản phẩm (`APP_NAME`, `appConfig.appName`) | Cố định ở mọi ngôn ngữ; lấy từ cấu hình, không từ message |
| Mã / enum / id (`AUTH_001`, `'business'`, `mode: 'tv'`, tên field API) | Là dữ liệu máy đọc. Hiển thị chúng thì tra khoá: `errors.http.codes.AUTH_001` |
| Path, URL, class CSS, `data-*`, id test | Không phải chữ hiển thị |
| `throw new Error('duplicate_code')` kiểu mã nội bộ không hiện ra | Chỉ để chặn luồng; câu hiện ra là khoá dịch |
| Nội dung do người dùng / BE nhập | Là dữ liệu; chỉ dịch phần khung quanh nó |
| Tên ngôn ngữ trong bộ chọn (`LOCALE_META[locale].label`) | Viết bằng CHÍNH ngôn ngữ đó ("Tiếng Việt", "English") để người dùng tìm được dù đang ở giao diện lạ |

## 9. Chuỗi metadata & SEO

- `<title>`, description từng trang: `messages/<locale>/metadata.json` → `metadata.<key>.{title,description}`; nền của root layout: `metadata.site` (`title`, `description`, `keywords`, `organizationDescription`).
  Trang thường gọi `generatePageMetadata({ params, key })` (`app/_seo/page-metadata.ts`) — `key` là `PageMetadataKey` (kiểu bắt thiếu khoá).
- Chữ trên trang công khai dịch ở Server Component (`landing`, `about`, `site`); JSON-LD, ảnh Open Graph (`landing.hero.title` + `metadata.site.description`) lấy từ message của ngôn ngữ đang render.
- Tên site không dịch (`getSiteName()` → `appConfig.appName`); câu mô tả thì dịch.
- Manifest PWA không theo ngôn ngữ URL nên dùng ngôn ngữ mặc định (`app/manifest.ts`).
- Chi tiết: `rules/seo/seo.md`.

## 10. Server hay client?

| | Server Component | Client Component |
|---|---|---|
| Hook | `useTranslations('ns')` (đồng bộ) | `useTranslations('ns')` — namespace PHẢI trong `CLIENT_NAMESPACES` |
| Async / `generateMetadata` | `await getTranslations({ locale, namespace })` từ `@/core/i18n/server` | — |
| Ngôn ngữ hiện tại | `requireLocale((await params).locale)` | `useLocale()` (từ `next-intl`) |
| Provider | `NextIntlClientProvider` đã bọc ở root layout — KHÔNG bọc thêm | — |

- ⛔ Client Component KHÔNG import `@/core/i18n/server` (kéo code server vào bundle) — dùng `@/core/i18n`.
- Chữ ở Server Component truyền xuống Client Component bằng props (đã dịch), không bắt client tự dịch lại.
- **Test**: component dùng `useTranslations` / `Link` / `useRouter` của `@/core/i18n` phải dựng qua `renderWithIntl` / `renderInRouter` (`tests/helpers/render.tsx` — provider next-intl với thông điệp THẬT); `render` trần ném "No intl context found". Kiểm cả hai ngôn ngữ khi chữ ảnh hưởng bố cục (`{ locale: 'en' }`).
